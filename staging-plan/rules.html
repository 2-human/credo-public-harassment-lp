A separate Webflow project isolates well: page settings, custom code, styles, assets, scripts and elements all live inside it, so editing and publishing staging.credolegal.com cannot change the other Webflow sites.

Rules on every step

  1. One site id. Every write uses the staging site id. Before each PBI Claude re-reads the site list and confirms its only domain is staging.credolegal.com; if not, work stops.
  2. Backup first. Before the first change: site and page custom code, registered scripts, page settings and SEO, styles and each page's element tree are exported, so any step can be rolled back.
  3. Publish to staging only. Publishing names the staging domain alone, once per PBI.
  4. Verify on staging.credolegal.com. Every change is measured on the published pages of staging.credolegal.com (all affected pages, phone and desktop) before it is called done. (Until 28 Sep the enroll and start sites were also fingerprinted; by the operator's decision of 28 Sep they are no longer checked.)
  5. No test data in the live lead systems. The automated checks answer every form post and analytics beacon themselves. A manual test lead on staging would enter the real lead pipeline, so none is sent until D1 decides where staging's form posts.
  6. Testing staging by hand. Staging sets UTM cookies on .credolegal.com, which the same browser then also sends to the other credolegal.com sites. Test in a private window, or clear credolegal.com cookies afterwards.

How each PBI runs

Edit on staging → publish to staging only → verify (lpcheck on the staging pages, plus the PBI's own “done when” check) → report → move the row to Done → take the next unblocked row. Only one row is in Doing at a time.
